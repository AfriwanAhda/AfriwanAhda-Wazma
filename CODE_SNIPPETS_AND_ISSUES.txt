BUG #1: Audio File Mapping Logic (Lines 51-55):

if (index==0) {

PROBLEM: Magic numbers (0 and 77) are hardcoded
- If index = 0: plays a1.mp3 (Al-Fatihah)
- If index = 1: plays a78.mp3 (An-Naba')

EXPLANATION: The list has Al-Fatihah (position 0) + Juz Amma (positions 1-36).
Juz Amma is chapters 78-114. This mapping is confusing and error-prone.

BUG #2: Memory Leak in play() Method (Lines 87-101):

public void play(int item) {
    /** Memanggil File MP3 */
    mp = MediaPlayer.create(this, item);  // <-- PROBLEM HERE

    try {
        mp.prepare();
    } catch (IllegalStateException e) {
        e.printStackTrace();  // <-- NO USER FEEDBACK
    } catch (IOException e) {
        e.printStackTrace();   // <-- NO USER FEEDBACK
    }

    mp.start();

    mp.setOnCompletionListener(new OnCompletionListener() {
        @Override
        public void onCompletion(MediaPlayer mp) {
            stateAwal();
        }
    });
}

ISSUES:
1. Line 89: Creates new MediaPlayer without releasing old one
   ISSUE: If user clicks play multiple times:
   - Old MediaPlayer instances remain in memory
   - Can cause OutOfMemory crashes
   
2. mp.prepare() on line 92 is unnecessary
   REASON: MediaPlayer.create() already calls prepare()
   
3. Error handling (lines 93-96) just prints to logcat
   ISSUE: User gets no feedback if audio preparation fails

PROPER FIX:

public void play(int item) {
    // Release previous player if exists
    if (mp != null) {
        try {
            mp.release();
        } catch (Exception e) {
            Log.e(TAG, "Error releasing MediaPlayer", e);
        }
    }
    
    mp = MediaPlayer.create(this, item);
    if (mp == null) {
        Toast.makeText(this, "Audio file not found", Toast.LENGTH_SHORT).show();
        return;
    }

    try {
        // mp.prepare() not needed - create() already prepared it
        mp.start();
        statePlay();
    } catch (Exception e) {
        Toast.makeText(this, "Error playing audio: " + e.getMessage(), 
                       Toast.LENGTH_SHORT).show();
    }

    mp.setOnCompletionListener(mp -> stateAwal());
}

BUG #3: No Resource Cleanup (Lines 148-151):

@Override

ISSUE: Should also release MediaPlayer resources. Better:

@Override
protected void onDestroy() {

Full Implementation (42 lines):

public class ListAdapter extends ArrayAdapter<String> {

    private int resource;
    private ArrayList<String> listSurah = new ArrayList<>();
    private LayoutInflater mInflater;

    public ListAdapter(Context context, int resource, ArrayList<String> objects) {
        super(context, resource, objects);
        this.listSurah = objects;
        this.resource = resource;
        mInflater = LayoutInflater.from(context);
    }

    @NonNull
    @Override
    public View getView(int position, @Nullable View convertView, @NonNull ViewGroup parent) {
        if(convertView == null) {
            convertView = mInflater.inflate(resource, null);  // <-- INEFFICIENT
        }
        TextView item = convertView.findViewById(android.R.id.text1);
        item.setText(listSurah.get(position));
        return convertView;
    }
}

OBSERVATIONS:
1. Line 35: Inflates null as parent parameter - inefficient
   BETTER: mInflater.inflate(resource, parent, false);
   
2. No ViewHolder pattern - creates new findViewById() every time
   IMPACT: Slower scrolling performance
   
3. Storing reference to entire listSurah array is redundant
   REASON: Parent class already has it via super()

BETTER IMPLEMENTATION:

public View getView(int position, @Nullable View convertView, @NonNull ViewGroup parent) {
    ViewHolder holder;
    
    if (convertView == null) {
        convertView = mInflater.inflate(resource, parent, false);
        holder = new ViewHolder();
        holder.text = convertView.findViewById(android.R.id.text1);
        convertView.setTag(holder);
    } else {
        holder = (ViewHolder) convertView.getTag();
    }
    
    holder.text.setText(getItem(position));
    return convertView;
}

private static class ViewHolder {
    TextView text;
}
